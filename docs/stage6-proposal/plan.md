# Предложение для этапа 6 — требуется согласование

Эти файлы — кандидаты для просмотра, пока не применены к конфигурации приложения.

1. API: Dockerfile с отдельными build/test/runtime стадиями. В runtime только
   скомпилированный API, production-зависимости, Prisma CLI и миграции.
   Prisma уже используется при каждом старте: перенести существующий пакет
   из devDependencies в dependencies, сохранив текущие версии и lockfile.
   Стадия test сохраняет инструменты для интеграции; рабочий контейнер их не содержит.
2. compose.vps.yaml: только API — init:true, cap_drop:ALL,
   security_opt:no-new-privileges:true, stop_grace_period:20s;
   после миграций запуск node через exec для корректного SIGTERM.
   Порты, volumes, .env, Caddy и работающая программа на 443 не меняются.
3. nginx.conf: server_tokens off; index.html/SPA без устаревшего кеша,
   хешированные /assets — immutable; отсутствующие assets и скрытые файлы — 404.
4. .dockerignore: исключить .env.*, архивы деплоя и временные UI-стенды.
5. Ежедневные локальные бэкапы через новый task-tg-backup.timer: 03:15 UTC
   (06:15 Москва), задержка до 5 минут, Persistent=true. Каталог
   /opt/task-tg/.backups/automatic, права 700, файлы 600; БД, исходники, .env,
   сертификаты Caddy и manifest. Блокировка flock от параллельных запусков.
   Хранение 7 суток, удаляются только собственные auto-* в этом новом каталоге.
   Ранее созданные ручные бэкапы и системные таймеры не затрагиваются.
   Это локальная копия на том же VPS, не внешний бэкап.
6. Проверка восстановления только в новой task_tg_restore_test, отказ если
   она уже существует; рабочую БД не перезаписывать. Отдельно проверить
   production-образ и интеграцию, затем последовательный деплой API/web.

Кандидаты Dockerfile/nginx/Compose и скрипта находятся рядом с этим планом.
Окончательные изменения применяются только после подтверждения пользователя.
